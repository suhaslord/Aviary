# Variable and option migrations

This directory stores machine-readable baselines for repository-wide migrations that need to land incrementally without allowing new technical debt during the transition.

## `get_option_defaults()` removal — issue #1251

`option_defaults_inventory.json` is generated by `tools/audit_option_defaults.py`. It records every Python call site, its subsystem domain, the receiving variable, and option keys that the surrounding test explicitly overrides after loading global defaults.

The baseline is intentionally a **ratchet**, not an allowlist forever:

1. `python tools/audit_option_defaults.py --check` fails if any file gains a new call or the repository-wide total increases.
2. A migration PR removes calls from one coherent subsystem or test family.
3. The same PR regenerates the manifest with `--write-manifest`, lowering the baseline.
4. Repeat until the count reaches zero, then remove `get_option_defaults()` itself.

The initial inventory contains **86 calls in 25 files**. The largest domains are GASP geometry (41 calls), aerodynamics (17), and two-DOF mission tests (13), so those are natural migration workstreams. The analyzer also found 230 explicit option overrides already present around these calls; those are useful starting points for reconstructing each test's minimal option contract.

### Review principle

A test should state the options its system-under-test actually depends on. Migration patches should not copy the full metadata defaults into tests just to make them pass. When a previously hidden option is required, set it deliberately with a value that makes the test intent clear.
